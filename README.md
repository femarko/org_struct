# 🗃️ Org Structure API

### API для управления подразделениями и сотрудниками организации с поддержкой древовидной иерархии департаментов

---

# 🎯 Описание проекта

### Функционал:

- создание подразделения
- поддержка иерархических деревьев подразделений
- создание сотрудников внутри подразделений
- перемещение подразделений в дереве
- удаление подразделений (cascade / reassignment)
- получение структуры с сотрудниками и вложенными подразделениями

### Ограничения:
- имя департамента уникально в пределах одного родителя
- запрещены циклы в дереве департаментов
- нельзя создать сотрудника в несуществующем департаменте
- удаление:
    - cascade — удаляет всё поддерево
    - reassign:
        - сотрудников переводит в другой департамент
        - дочерние департаменты переподчиняет родителю удаляемого
          департамента
---

# 🏛️ Архитектура
### 📜 Принципы:
- Clean Architecture (DDD-light)
- слоистость (domain / infrastructure / interfaces)
- dependency inversion через Protocol
- бизнес-логика изолирована от БД и интерфейса
- "тонкий" HTTP слой
- транзакции управляются инфраструктурой

### ⚖️ Упрощённая доменная модель
Используется единая модель (SQLAlchemy ORM = domain entity)

Мотивы:
- CRUD-ориентированный домен без сложных бизнес-инвариантов
- стремление сократить boilerplate код

Компромисс:
- домен частично связан с ORM-моделью (отсутствует слой маппинга)
- но остаётся независимым от БД,сессий и транзакций за счёт использования
  репозиториев и DI через FastAPI
---

# 🧪 Подход к тестированию

### 📦 Изолированные юнит-тесты доменного слоя

- domain/services тестируются без подключения к БД
- используются fake-репозитории
### 🔌 Интеграционне тесты
- интеграционные тесты проверяют взаимодействие сервиса с БД
- используются реальные ORM-сессии

# 🐳 Запуск проекта

```bash
docker compose up --build   # запуск приложения, БД, PGAdmin
docker compose down -v      # остановка приложения и окружения
```
✅  Миграции выполняются автоматически  
⚠️ `.env` используется только для демо-запуска, в production
    рекомендуется использовать secret management
